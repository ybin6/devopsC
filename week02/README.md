## 서버
* 서버는 하드웨어와 소프트웨어이다.
	* 하드웨어로서 서버 - 전원을 켜다/끄다
	* 소프트웨어로서 서버 - 서버를 설치하다


## 서버의 역할 (frat.클라이언트)
어원 - Serve (뜻: 무엇인가를 제공하다)
Server - 무언가를 제공하는 주체
Client
- Request : 서버로부터 무언가를 받으려면 원하는 것을 요청해야함
- Response : 이 요청에 대한 응답


## 서버 운영 방법
* 베어메탈 (bare metal) - PC 한대에 OS 설치 후 여러 소프트웨어 운영
가상화 기술
* 하이퍼바이저 (hypervisor) - PC한 대에 여러 가상 머신
* 컨테이너 (container) - PC 한 대에 여러 컨테이너 


## 가상화
* 서버에 적용되는 기술
	* 실제 서버가 존재하지 않더라도 마치 있는 것처럼 만드는 기술
* 물리적인 컴퓨팅 환경 내에서 여러 개의 논리적인 컴퓨팅 환경 만들 수 있는 기술
	* 물리적 = 실제로 존재
	* 논리적 = 가상으로 존재
* 즉, 컨테이너는 서버를 효율적으로 사용하기 위한 **가상화** 기술


#베어메탈 방법의 장단
장점
* 하나의 OS에서 모든 프로그램 관리 쉬움

단점
* 프로그램 하나가 해킹 당할 때, 다른 프로그램 정보도 위험
* 프로그램 하나의 리소스(자원) 사용량이 급증할 때 나머지 프로그램이 비정상 작동 가능성
-> 단점 해결 위해 가상화 기술 통해 **격리된 공간**에서 소프트웨어 실행




## 하이퍼바이저
전통적 가상화 기술
여러 가상 머신이 하나의 물리 하드웨어 공유할 수 있도록 리소스를 가상화하고 관리
프로그램 -> 시스템 콜 -> 게스트OS 커널 -> 가상 하드웨어 -> 하이퍼바이저 -> 실제 하드웨어


* 호스트OS
	* 하이퍼바이저 실행하는 OS
	* 물리적인 하드웨어 서버를 관리
* 게스트OS
	* 가상 머신
	* 리소스 할당(CPU, 메모리, 디스크, 네트워크)
* 기본 상식
- 프로세스를 실행하기 위해서 리소스 필요 - 하드웨어 리소스를 사용하기 위해 OS 리소스 사용을 요청
- 커널 - 프로그램 요청 받아 하드웨어 리소스 안전하게 관리하고 연결, 프로세스 리소스 사용 요청 처리위한 시스템 콜 제공




## 컨테이너
하이퍼바이저와 차이점
* 하이퍼바이저 가상화보다 가볍고 빠름
* 호스트OS, 게스트OS 커널이 독립적으로 존재 -> 오버헤드 커짐

* 별도의 게스트 OS 커널 없이, 호스트OS의 커널 기능으로 격리된 공간 만들 수 있음
	* 모든 컨테이너가 호스트OS 커널 공유(호스트OS와 다른 종류의 OS를 실행할 수 없음
* 리눅스 컨테이너의 핵심 기술
	* 네임스페이스 : 프로세스, 파일 시스템, 네트워크 등의 격리
	* 제어 그룹 기술: 리소스 사용량 제어 



## WSL (Windows Subsystem for Linux)
* 특장점
	* 빠른 속도(가상 머신 보다 적은 리소스 사용)
	* 시스템 통합(윈도우 파일 탐색기에서 쉽게 접근 가능)
	* 편리한 개발(bash 명령어를 그대로 사용 가능)

* 파워셸
	* 마이크로소프트가 개발
	* 스크립트 작성 및 실행이 가능한 CLI
	* 관리자 권한으로 실행



1, 인스톨: wsl --install
2, 우분투 설치: wsl --install -d Ubuntu-24.04
3, 기본으로 실행할 배포판 설정: wsl --set-default Ubuntu-24.04
4, Ubuntu 터미널로 들어가기
* wsl
* wsl -d Ubuntu-24.04
* Ubuntu 터미널 시작 - username@computer_name:/mnt/c/Users/pc_name$
* 파워셸로 돌아오기 - exit

## Git
버전 관리 시스템 = 코드의 변경 이력 관리하는 도구
- 파일 변경이력 기록하고 관리하는 도구
- 이전 버전으로 돌아가거나 변경 내용을 비교 가능
- 여러 브랜치 만들어 독립적으로 작업 가능
- 인터넷 연결 없이도 로컬에서 사용 가능

깃 초기화
git init

깃 커밋
git status - 현재 상태 보기
git add - 파일 추가
git commit -m "커밋메시지" - 커밋메시지 추가


커밋 변경
git switch -d 커밋해시

커밋 변경 비교
git diff 커밋해시1 커밋해시2


## 브랜치 - 특정 커밋 가리키는 이름, 서로 다른 작업 독립적으로 진행할 수 있음
git switch -c 브랜치명 - 브랜치 만들기
git switch 브랜치명 - 브랜치 이동
git branch - 현재 브랜치 확인
git log --oneline --all --graph - 브랜치 포함한 현재 상태 그래프로 보기



## GitHub - git 기반 온라인 협업 플랫폼
- git 저장소를 온라인에 저장 및 공유
- 여러 사람이 같은 프로젝트를 함께 개발 가능
- Pull Request, lssue, code Review 등 협업 기능 제공
- CI/CD,gitnub actions 등 DevOps기능 제공

gh 인스톨
sudo apt update
sudo apt install gh -y

gitnub 로그인
gh auth login

리포지토리 만들기
gh repo create 레포이름 --public --source=. --remote=orgin --push
--public 공개 저장소 생성
--source=. 현재 디렉터리의 git 저장소를 github에 연결
--remote=origin 원격 저장소 이름 지정
origin 연결된 원격 저장소에 관례적으로 사용하는 이름
--push 로컬의 커밋을 원격 저장소에 업로드 



웹에서 확인
gh repo view --web - 웹에서 보기
gh browse --no-browser - 링크보기

커밋 후 푸시(이래야 깃허브에 올라감)
git push
